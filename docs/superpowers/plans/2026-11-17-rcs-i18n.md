# RCS Internationalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every user-visible string in the RCS web UI come from a `zh-CN`/`en` catalog, persist a per-user language choice, and format dates in the active locale without changing any CLI/worker protocol.

**Architecture:** A pure locale core (`src/i18n/locales.ts`) owns supported locales, cookie name, and Accept-Language negotiation. JSON catalogs feed `next-intl` through one request config; the app is split into three per-area root layouts (`(main)`, `(auth)`, `(offline)`) so only the authenticated and login trees read cookies, while `~offline` stays static and precacheable. `users.locale` is nullable and validated only at the API boundary.

**Tech Stack:** Next.js 16.4 App Router, React 19, next-intl 4.15, Hono gateway, Drizzle/Postgres, Auth.js v5 beta, `bun test`.

**Spec:** `docs/superpowers/specs/2026-11-17-rcs-i18n-design.md`

## Global Constraints

- Locale is never in the URL; `basePath: /code` and all existing paths stay unchanged.
- Resolution order is exactly: valid `rcs_locale` cookie → browser `Accept-Language` → `zh-CN`.
- `users.locale` is `text` nullable with no default and no DB check constraint; `NULL` means "never chose".
- Catalog keys only in code; tests assert keys, codes, and behavior, never prose.
- `v1`/`v2`/`acp` response bodies stay byte-identical: never pass a `code` to `jsonError` from those routes.
- The Edge middleware and the Auth.js JWT stay untouched: no locale claim, no DB access there.
- `~offline` must remain statically prerenderable and precached; it may not import `next/headers` or `src/i18n/server.ts`.
- No global `next-intl` type augmentation: dynamic keys (`status.*`, `errors.codes.*`) are validated by catalog tests, not `tsc`.
- All commands run from `packages/rcs`; commits run from the repo root. Formatting: no semicolons, single quotes, 2-space indent, 120 columns.
- React/Next imports in `packages/rcs` are extensionless; gateway imports keep the `.js` suffix.

## Review Focus

- **Shared browser, two accounts:** signing out or signing in must overwrite/delete `rcs_locale`; a stale cookie from the previous user is the bug. Task 1 (`nextLocaleCookie`) and Task 7 (login/sign-out) pin it.
- **Accept-Language shapes:** `zh-TW`, bare `zh`, `en-GB`, q-weights, `*`, and malformed values must resolve deterministically and never throw. Task 1 tests all of them.
- **Offline precache after the layout split:** `~offline` must stay static; one `cookies()` call in its layout silently turns it dynamic. Task 3 adds a source-level guard.
- **Split-host dev:** the language selector must call the Next origin at `/code/api/preferences`, not the gateway on `:4000`, or the cookie never lands. Task 6 pins the URL constant.
- **Unknown server codes:** a code the client does not know must fall back to the raw message; `t()` throws on missing keys in development. Task 8 tests the fallback.

```ts
function flatten(value: unknown, prefix = ''): Map<string, string> {
  const out = new Map<string, string>()
  if (value && typeof value === 'object' && !Array.isArray(value)) {
    for (const [key, child] of Object.entries(value)) {
      const path = prefix ? `${prefix}.${key}` : key
      for (const [k, v] of flatten(child, path)) out.set(k, v)
    }
  } else if (typeof value === 'string') {
    out.set(prefix, value)
  }
  return out
}

const placeholders = (text: string): string[] => [...text.matchAll(/\{\s*(\w+)/g)].map((match) => match[1] ?? '').sort()
```

```ts
import en from '../../messages/en.json'
import zhCN from '../../messages/zh-CN.json'

import type { Locale } from './locales'

export type Messages = typeof en

export const CATALOGS: Record<Locale, Messages> = { en, 'zh-CN': zhCN }

export function loadMessages(locale: Locale): Messages {
  return CATALOGS[locale]
}
```

```ts
// src/i18n/server.ts
import { cookies, headers } from 'next/headers'

import { LOCALE_COOKIE, resolveLocale, type Locale } from './locales'

export async function resolveRequestLocale(): Promise<Locale> {
  const [jar, incoming] = await Promise.all([cookies(), headers()])
  return resolveLocale({
    cookie: jar.get(LOCALE_COOKIE)?.value ?? null,
    acceptLanguage: incoming.get('accept-language'),
  })
}
```

```ts
// src/i18n/request.ts
import { getRequestConfig } from 'next-intl/server'

import { loadMessages } from './catalogs'

export default getRequestConfig(async () => {

  return { locale, messages: loadMessages(locale) }
})
```

```ts
// src/app/api/preferences/route.ts
import { NextResponse } from 'next/server'

import { LOCALE_COOKIE, localeCookieOptions } from '../../../i18n/locales'
import { auth } from '../../../lib/auth'
import { setUserLocale } from '../../../lib/preferences'
import { getRepositories } from '../../../lib/repos'

export const runtime = 'nodejs'

export async function POST(request: Request): Promise<Response> {
  const session = await auth()
  if (!session?.user?.id) {
    return NextResponse.json({ error: 'unauthorized', code: 'unauthorized' }, { status: 401 })
  }

  const body: unknown = await request.json().catch(() => null)
  const result = await setUserLocale(getRepositories(), session.user.id, body)
  if (!result.ok) {
    return NextResponse.json({ error: 'invalid locale', code: result.code }, { status: 400 })
  }

  const response = NextResponse.json({ locale: result.locale })
  response.cookies.set(LOCALE_COOKIE, result.locale, localeCookieOptions())
  return response
}
```
