# 升级到 2.1.89：可读源码与版本无关恢复流水线

- 日期：2026-11-03
- 状态：设计待评审
- 作者：Claude + sobird

## 1. 背景

本仓库的 `src/` 来自 `scripts/generate-source-code.ts`：它读取 2.1.88 的 `cli.js.map`，把 `sourcesContent` 还原成 TypeScript 源码。因此：

- 根目录 `cli.js`（14.7 MB，含 `cli.js.map`）是 **2.1.88**；
- `package/cli.js`（13.1 MB）是 **2.1.89**，与 npm 官方包逐字节一致；
- **2.1.88 从未公开发布**（npm 版本序列 2.1.87 → 2.1.89）；
- **2.1.89 没有 sourcemap**，无法像 2.1.88 那样机械还原。

目标产物是“可读、可继续开发的 2.1.89 源码”，用于研究实现思路与二次开发，而不是可执行文件对拍。

## 2. 目标

- G1：让 `src/` 覆盖 2.1.89 的**全部用户可见/行为变化**，以符合仓库风格的可读 TS 表达。
- G2：交付一套**版本无关的恢复流水线**，以“参照版 bundle + map”和“目标版 bundle”为输入，2.1.90、2.1.91 可直接复用。
- G3：建立可重复的三层验证：构建健康、bundle 对拍、冒烟运行。
- G4：留下可审计的变更台账（每条变化的状态、证据、验证方式）。

## 3. 非目标

- 不追依赖版本与第三方库代码（两 bundle 约 1.67 MB 的依赖差异，如 Azure MSAL、DOM/XML、URL 解析等）。
- 不保证与官方 bundle 字节级或源码级一致；无 map，部分逻辑只能行为近似。
- 不删除仓库中 ant-only / 内部专用代码（目标 external bundle 缺失不等于应删除）。
- 不还原服务端配置、Statsig 实验参数或私有后端逻辑。
- 不移植纯彩蛋的日期表现；保留其 gate 结构即可。

## 4. 约束与事实

- 参照物：`cli.js` + `cli.js.map`（2.1.88）。目标：`package/cli.js`（2.1.89）。
- 打包器会按出现频率重命名标识符：同一段源码在两个 bundle 中可能得到不同短名。因此对齐**不能靠文本匹配**，必须基于 AST 结构 + 字符串字面量指纹。
- 外部目标 bundle 会 tree-shake 内部代码；仓库源码含大量 `feature('...')` 门控分支，移植时保留。
- 工具链：Bun 运行脚本；`typescript` 提供 AST 解析/打印；`source-map` 与 `ws` 已在依赖中；调试探针用 `node --inspect-brk` + CDP。
- 仓库约定：`.js` 相对导入、无分号、单引号、2 空格、120 列；特性开关必须写成字面量 `feature('NAME')`。
- 完成标准（用户已确认）：三层都跑通。
- 现有构建有个已知不一致：`bunfig.toml` 的 `MACRO.VERSION` 是 2.1.88，而 `scripts/build.ts` 走 `scripts/config.ts`，其 `MACRO.VERSION` 取自 `package.json` 的 `1.0.0`。见 D6。

## 5. 范围定义

纳入范围的变化分三类，全部进入台账：

1. **官方 2.1.89 changelog** 的 52 条。
2. **bundle 可见但 changelog 未记录**的行为变化，例如：`/autocompact`、`/brief`、`/buddy`、`/web-setup`、channels（`--channels`、`channelsEnabled`、`defaultView`）、fast mode 错误 UX、PowerShell 安全规则、sandbox MITM/proxy 配置、agent/skill memory 文件权限。
3. **不纳入**：第三方依赖内容、纯打包顺序差异、无法从压缩代码判定语义的服务端逻辑。

每条变化必须落入一个状态：

- `already-present`：2.1.88 bundle 已有等价实现，无需改源码；
- `ported`：本次已移植；
- `approximated`：按行为近似实现，记录无法确认的点；
- `ignored-dependency`：依赖差异，明确不处理；
- `retained-internal`：目标 bundle 中已移除，但按 D5 有意保留在 `src/` 的内部/ant-only 代码；`verify` 对这类差异放行，需附保留理由；
- `unresolved`：仍无法判定，需继续深挖。

## 6. 通用恢复流水线（`scripts/upgrade/`）

### 6.1 命令入口

```
bun scripts/upgrade/cli.ts <subcommand> [options]

inventory --bundle <file> --out <json>
align     --reference <bundle> [--map <map>] --target <bundle> --out <dir>
extract   --align <align.json> --target <bundle> --out <dir>
probe     --target <bundle> --scenario <file> --out <json>
verify    --target <bundle> --src <dir> --status <status.json> --out <report>
```

所有子命令只读 bundle、只写输出目录，不直接改 `src/`。

### 6.2 `inventory`

从 bundle 提取稳定清单，输出 JSON + Markdown：

- 版本号、SHA-256、字节数；
- 命令注册表：`type:"local|local-jsx|prompt", name:"..."`；
- 环境变量：`CLAUDE_CODE_[A-Z0-9_]+`，外加显式登记的非前缀变量（如 `MCP_CONNECTION_NONBLOCKING`）；
- 字符串字面量：自写扫描器，正确处理引号、转义与模板字符串；
- CLI flag：`new f3("--x"` / `.option("--x"` 等模式；
- 可选：schema 枚举等定点提取。

### 6.3 `align`

流程：

1. 用 TypeScript `createSourceFile(..., { allowJs: true })` 解析参照与目标 bundle。
2. 为每个函数/代码块计算指纹：排序后的字符串字面量集合 + 忽略标识符名的 AST 节点类型序列（S-expression）。
3. 以指纹 + 父节点上下文做匹配；有 `--map` 时，用参照版 sourcemap 把匹配到的参照位置映射回**原始源文件、行号、函数名**。无 map 时降级：优先沿台账链条继承归属（见下），其次用结构/字面量指纹匹配仓库 `src/` 中已有文件，仍未命中的标 `unattributed` 并降低置信度。
4. 对形状一致的节点，按子节点位置对齐，得到局部标识符重命名表（目标短名 → 参照原名）。
5. 匹配不上的节点标记为 `new`/`changed`，附上下文。
6. 输出 `align.json`：目标节点范围、原始文件/名称、置信度、变更分类。

已知风险：对 13 MB 单文件做 TS AST 解析较慢、内存高。缓解：提高 `--max-old-space-size`，必要时按顶层分块解析；若不可行，退化为“字符串指纹 + 括号配对”的分块扫描，并在报告中降级置信度。

**无 map 的归属链（D8）**：目标节点 →（结构/字面量指纹）参照节点 → 台账中该参照节点上一版的归属（原始文件/名称）。沿 `docs/upgrade/<version>/align.json` 逐版继承，因此 2.1.90 起即使参照版无 map 也能保持归属；每跳降一档置信度并记录。

**依赖噪声判定规则（固定，不逐次手调）**：

1. 有 map 时，参照节点映射到 `../node_modules/**` 的一律 `ignored-dependency`，不再参与匹配。
2. 无 map 时，目标专属节点先与“已知依赖字符串集合”（从参照 map 的 node_modules `sourcesContent` 提取）比对，命中即 `ignored-dependency`。
3. 其余目标专属节点按大小与字面量指纹分桶；只有命中 changelog / bundle-only 关键词（命令名、env 名、UI 文案）的进入 `extract` 候选，其余默认 `ignored-dependency` 并在报告中列计数，供人工抽样。
4. 无法归入上述三类的节点标 `unresolved`，进入人工深挖队列。

### 6.4 `extract`

- 对 `changed`/`new` 节点输出美化后的候选代码（TypeScript printer，必要时再用 oxfmt 统一风格）。
- 附上继承的命名建议、命中的字符串提示、所属原始源文件。
- 产物写入 `candidates/`，**不自动合并**；合并由人工/后续实现步骤完成。

### 6.5 `probe`

把“动态验证”固化成可复用的场景文件：

```jsonc
{
  "args": ["--version"],
  "env": { "...": "..." },
  "stdin": null,
  "breakpoints": [{ "script": "package/cli.js", "line": 1234, "column": 56, "label": "defer-decision" }],
  "capture": ["args", "return", "fn.toString"],
}
```

执行流程：

1. `node --inspect-brk=0 <target> <args>` 启动子进程，从 stderr 解析 inspector URL。
2. 通过 `ws` 连接 CDP：`Runtime.enable`、`Debugger.enable`。
3. 按 `scriptId + line/column` 设置断点并恢复执行。
4. 命中 `Debugger.paused` 时：
   - 记录调用栈（函数短名、位置）；
   - 用 `Debugger.evaluateOnCallFrame` 取实参、局部变量、指定表达式；
   - 需要时执行 `fn.toString()` 导出闭包函数源码；
   - 需要“函数调用断点”时，先在可求值的父帧拿到函数引用，再用 `Debugger.setBreakpointOnFunctionCall`。
5. 超时/退出时清理进程，输出 JSON trace。

安全约束：探针只在本机运行，不上传任何数据；不修改目标 bundle。

### 6.6 `verify`

- 从目标 bundle 重新计算 `inventory`。
- 从参照 bundle（默认 `cli.js`）计算 `inventory`，用于识别“目标已移除”的项。
- 从 `src/` 计算对应清单：
  - 命令：解析 `src/commands.ts` 注册项与各命令的 `name`；静态包含 `feature()` 门控的注册，不评估开关；
  - env / 字符串：全 `src/` 文本扫描（门控代码同样计入“存在”）；
  - 关键 schema 枚举：定点解析（如 `permissionBehaviorSchema`）。
- 对账分三组：
  - **目标有、src 无**：必须标记 `ported` / `approximated`，否则失败；
  - **目标无、src 有**：必须标记 `already-present`（参照本来就有）/ `retained-internal`（按 D5 有意保留），否则失败；
  - **关键字符串/枚举缺失**：按条目状态核对。
- 与台账 `status.json` 对账：每个差异必须落入一个终态；`unresolved` 视为未完成。
- 存在未登记差异或状态为 `unresolved` 时退出码非 0。
- `verify` 只做静态对账；“行为是否等价”由命中节点复核与第三层冒烟兜底。
- 输出 `report.md` + `report.json`。

### 6.7 台账结构

`docs/upgrade/2.1.89/status.json`：

```jsonc
{
  "source": { "reference": "2.1.88", "target": "2.1.89" },
  "entries": [
    {
      "id": "cmd:autocompact",
      "kind": "command",
      "status": "ported",
      "evidence": ["bundle:name:\"autocompact\"", "probe:scenario-autocompact.json"],
      "notes": "新增命令与窗口配置 UI",
    },
  ],
}
```

配套 `status.md` 供人阅读，`notes.md` 记录近似实现与未解点。

## 7. 移植工作流与批次

每条变化按固定流程处理：

1. `inventory` 找到差异 → 2. `align`/`extract` 定位到源文件与候选代码 → 3. 阅读 2.1.88 源码上下文并写符合仓库风格的 TS → 4. 对分支/阈值/时序不明确处用 `probe` 确认 → 5. 补测试（可行时）→ 6. `verify` 登记状态。

批次（按依赖与风险排序）：

- **A. 基础设施**：打通 `inventory` / `align` / `extract` / `verify`，先产出 2.1.88→2.1.89 台账初稿。
- **B. 命令面**：`/autocompact` 新增；`/brief`、`/buddy`、`/web-setup` 按 2.1.89 版本更新并调整特性开关；`/ultraplan` 从外部命令面移除。
  - 现状：`src/commands/brief.ts`、`src/commands/remote-setup/index.ts`、`src/commands/buddy/`、`src/buddy/` 已存在但被 `BUDDY`、`KAIROS_BRIEF` 等开关关闭；`src/commands/ultraplan.tsx` 存在且 `ULTRAPLAN` 开启。
- **C. 权限与 hooks**：`PreToolUse` 增加 `"defer"` 的**完整 headless pause/resume 协议**（D9）：schema/类型/文档串（`src/utils/permissions/PermissionRule.ts`、`src/types/hooks.ts`、`src/utils/hooks.ts`）；`-p` 命中 `defer` 时暂停并输出可恢复状态；`-p --resume` 重新评估 hook；仅 print 模式生效；仅 solo tool call（有兄弟调用会在恢复时被孤立，按 2.1.89 行为拒绝或特殊处理）。具体状态与文案以 `probe` 取得的 2.1.89 行为为准。
- **D. 上下文与压缩**：autocompact 窗口配置与 thrash 检测；`cleanupPeriodDays` 改为正数校验并更新描述。
- **E. 工具行为**：Bash 修改文件后的 stale-edit 提示、Edit-after-Bash、`MCP_CONNECTION_NONBLOCKING`。
- **F. 环境变量**：新增/移除/改名，并同步 `docs/environment-variables.md`。
- **G. 其余 changelog 项**：对初步判定为 `already-present` 的条目用 `probe`/定点扫描复核；对 `unresolved` 深挖。
- **H. bundle-only 功能**：channels、brief 模式、web setup 流程、fast mode 错误 UX、PowerShell 安全规则、sandbox proxy/MITM 配置、agent/skill memory 权限。逐项取证后决定 `ported` 或 `approximated`。
- **I. 文档与收尾**：台账、README 的升级说明、版本宏、最终三层验证。

## 9. 验证计划（三层，全部必须跑通）

### 9.1 第一层：构建健康

- `bun run typecheck`
- `bun run build`
- `bun run fmt:check`（至少覆盖改动文件）
- `bun test`
- `bun run lint`：仓库有历史遗留错误，只处理本次改动文件引入的失败

### 9.2 第二层：bundle 对拍

- `bun scripts/upgrade/cli.ts verify --target package/cli.js --src src --status docs/upgrade/2.1.89/status.json`
- 要求：命令、env、关键 schema、关键字符串全部对账；每条差异有终态；无 `unresolved`。
- 验收（D10）= `verify` 全绿 + 台账全部终态 + 人工复核 `align` 输出中命中 changelog / bundle-only 关键词的 `changed` 节点；依赖噪声不逐条复核。

### 9.3 第三层：冒烟运行

运行策略（D11）：离线优先。`--version`、`--help`、参数校验、`cleanupPeriodDays: 0` 等必须离线跑通；需要模型回合的 `defer`、`MCP_CONNECTION_NONBLOCKING`、`/autocompact` 可用本机真实 API 凭据手工跑，并在 `notes.md` 标注为非 CI 步骤。冒烟对象是 `bun run build` 产出的 external bundle，确保 `feature()` 门控结果与 2.1.89 外部包一致。

- `bun run dev --version` 输出 2.1.89。
- `--help` / 命令注册面包含新命令。
- 非交互场景：
  - `PreToolUse` hook 返回 `defer` 时，headless 暂停/resume 路径；
  - `cleanupPeriodDays: 0` 触发校验错误；
  - `MCP_CONNECTION_NONBLOCKING=true` 时 `-p` 不等待 MCP；
  - `/autocompact` 参数解析与重置。
- TUI 场景尽量复用 `tests/testing/ink.tsx` 或 tmux 冒烟；无法自动化时记录人工步骤。
- `probe` 场景中可确定的部分转为断言，纳入回归。

- `docs/upgrade/2.1.89/{status.json,status.md,notes.md}`：台账与说明。

## 11. 风险与未知

- 无 map：部分压缩逻辑可能只能近似；必须在台账中显式标注 `approximated`。
- 服务端/Statsig 门控功能（channels、web setup、fast mode）无法在本地完整触发，只能移植结构与文案。
- AST 解析大文件的性能与内存风险。
- 两 bundle 的依赖差异会污染静态 diff，流水线需要严格的依赖噪声过滤规则。
- 仓库源码含内部代码，`align` 不能据此删除文件；只增改与目标行为相关的部分。
- lint 历史遗留导致“全绿”不可达，验证以改动文件为准。

## 12. 已确定的实现决策

- **D1**：范围 = 官方 changelog + bundle 可见行为变化；依赖对齐排除。
- **D2**：流水线版本无关，输入参照 bundle+map 与目标 bundle。
- **D3**：动态调试固化为 `probe` 场景，而非临时操作。
- **D4**：完成标准 = 三层验证全部通过。
- **D5**：`src/` 中已有的内部/ant-only 代码保留，不因目标 bundle 缺失而删除。
- **D6**：引入显式的上游版本常量（避免 `scripts/config.ts` 用 `package.json` 的 1.0.0 作为 `MACRO.VERSION`）；`bunfig.toml` 与构建期保持一致，`package.json` 的版本继续代表本 fork 的发布版本。
